## 0. Orientation — which machine learning, and why there are two

Before the five elements can be named, one question has to be settled, because
a panel will ask it in the first two minutes:

> **"You are studying a large language model. What exactly is being learned?"**

**The language model is not being trained.** Qwen2.5-1.5B-Instruct is loaded
frozen and run through `llama.cpp` (Gerganov, 2023). It is the *objective
function being measured*, not the learner. Fine-tuning it would change the
objective mid-study and invalidate every energy comparison, because the baseline
condition and the BOPIS condition would no longer be running the same model.

BOPIS contains exactly **two genuinely learned components**, and they are
different kinds of learning:

| # | Component | Implementation | Learning paradigm |
| :--- | :--- | :--- | :--- |
| **A** | **Gaussian Process surrogate** inside the Bayesian Optimization loop | `bopis/gp.py`, `bopis/optimizer.py` | **Supervised regression**, operated under **active learning** (sequential experimental design) |
| **B** | **Multinomial Naive Bayes task classifier** | `bopis/classify_trained.py` | **Supervised multiclass classification** |

A third stage — Pareto non-dominated sorting (`bopis/pareto.py`) — is
**not learning at all.** It is a deterministic selection algorithm. Do not let it
be described as "unsupervised learning"; it sorts, it does not learn, and
misnaming it costs credibility on an otherwise correct answer.

**Nothing in BOPIS is unsupervised. Nothing in BOPIS is reinforcement learning.**
Bayesian Optimization shares the exploration/exploitation trade-off with RL — that
is precisely what Expected Improvement balances — but it has no state, no state
transitions, no learned policy and no temporal credit assignment. Evaluating one
configuration does not change the environment for the next. Formally it is a
structured bandit with a Gaussian Process prior; the defensible phrasing is
*"bandit-adjacent, not reinforcement learning."*

### How this document is organised

Component **A** (the GP surrogate) is **the thesis's proposed model** — it is the
contribution. Component **B** (the classifier) is the component whose five
elements are instantiated with fully real, measured data.

Each of the five sections below therefore treats **both**, A first and B second.
Read A for the contribution; read B for the cleanest textbook illustration of
each element.

### Where the five-element framing comes from

The decomposition is standard and can be cited:

- **Mitchell (1997)** gives the canonical definition: a program learns from
  *experience E* with respect to *task T* and *performance measure P*. That is
  our Data, Task and Evaluation.
- **Domingos (2012)** decomposes every learning algorithm into
  **representation + evaluation + optimization** — our Model, Evaluation and
  Learning Algorithm respectively.
- **Flach (2012)** organises the whole field as *tasks → models → features*,
  which is the Task / Model / Data axis.

### Summary table — the answer in one page

| Element | **A — Gaussian Process surrogate** | **B — Naive Bayes classifier** |
| :--- | :--- | :--- |
| **1. Data** | 30 configuration–energy observations, `(x, E)`, generated by the learner itself | 15,011 human-labelled Dolly 15k rows; 10,507 / 2,251 / 2,253 stratified split |
| **2. Task** | Supervised **regression** over a 5-dimensional configuration space, in service of black-box **optimization** | Supervised **multiclass classification**, 8 classes |
| **3. Model** | Gaussian Process with RBF (squared-exponential) kernel; 3 hyperparameters `θ = {σ_f², ℓ, σ_n²}` | Multinomial Naive Bayes with add-α (Lidstone) smoothing; 8,081 features |
| **4. Learning algorithm** | Maximize the **log marginal likelihood** — log-space grid search + multi-start Nelder–Mead — refitted after every evaluation; next point chosen by **Expected Improvement** | **Closed-form maximum likelihood** by counting; α selected on validation |
| **5. Evaluation** | LOOCV: **R² = 0.980**, NPE = 3.77%, MAE = 4.70 J, UCR = 0.967 | Held-out test: **69.7%** exact 8-way vs **48.2%** rule baseline (**+21.4 pts**) |

## ELEMENT 1 — DATA

> *"Experience E"* (Mitchell, 1997). What the learner learns **from**.

### 1A — Data for the Gaussian Process surrogate

This is the element most often misunderstood on our own team, so state it
precisely:

**There is no pre-existing training set, and there is no training phase.**
The GP's data is **created by the learner, one point at a time, during the
search.** This is what makes it *active learning* rather than ordinary supervised
learning (Settles, 2009).

**Unit of observation:** one fully executed inference run of an entire
50-prompt proxy workload under one fixed configuration.

**Input (features), `x`** — the configuration vector `x = (t, b, p, g, c)`,
defined in Table 3.2 and implemented in `bopis/config_space.py`:

| Symbol | Parameter | Domain | Cardinality |
| :--- | :--- | :--- | ---: |
| `t` | Maximum generated tokens (`n_predict`) | {128, 256, 512, 1024} | 4 |
| `b` | Parallel server slots (`--parallel`) | {1, 2, 4, 8} | 4 |
| `p` | GGUF precision / quantization variant | {F32, F16, Q8_0, Q4_K_M} | 4 |
| `g` | Transformer layers offloaded to GPU (`--n-gpu-layers`) | {0, 14, 28, all} | 4 |
| `c` | CPU threads (`--threads`) | {2, 4, 8} | 3 |

**Total configuration space: 4 × 4 × 4 × 4 × 3 = 768 configurations.**

Because a GP requires a continuous metric space, each `x` is encoded into
**five real-valued dimensions**, `("t", "b", "p_bpw", "g_frac", "c")`, each in
[0, 1] (`bopis/config_space.py:151`). Two encoding decisions are worth
defending, because both are places a panel could reasonably push:

1. **The four ordinal parameters are log2-scaled before normalisation**, not
   normalised linearly. Their effect on cost is *multiplicative* rather than
   additive — doubling generated tokens roughly doubles decode energy, and
   halving bits-per-weight roughly halves memory traffic. So `t = 128, 256, 512,
   1024` maps to an evenly spaced `0, ⅓, ⅔, 1`, which is what makes a single
   isotropic length scale meaningful across the dimension.
2. **Precision is encoded as normalised log2 bits-per-weight, not one-hot.**
   F32 → 32, F16 → 16, Q8_0 → 8.5, Q4_K_M → 4.83 (the 8.5 and 4.83 are
   llama.cpp's measured figures; block quantization carries scale/min metadata,
   so the variants are not exactly 8 and 4 bits). One-hot would add three
   dimensions — an 8-dimensional input for at most 30 observations, far too
   sparse to fit a length scale to — and would discard the natural ordering
   F32 > F16 > Q8_0 > Q4_K_M that the surrogate can otherwise exploit. It also
   makes the kernel's smoothness assumption physically true: Q8_0 and Q4_K_M
   really are *nearer neighbours* than F32 and Q4_K_M.

**Target (label), `y`** — a single continuous scalar: **`energy_j`**, the total
estimated energy in joules consumed executing the proxy workload under `x`.

> ⚠️ **Critical clarification, and a frequent misunderstanding within the team:**
> **the GP models energy only.** Confirmed in `bopis/optimizer.py` — the surrogate
> is fitted on `energy_j`, and the recorded `gp_prediction_pairs` compare μ against
> measured *energy*. Speed and quality are **not** learned by the GP. They enter
> afterwards, through Pareto sorting and the SRR/QRR constraint floors (§4A).

**Sample size: n = 30.** The complete budget, from `bopis/optimizer.py`:

```
10 prior-weighted random seed evaluations   (no surrogate exists yet)
+ 20 BO-guided evaluations                  (each chosen by Expected Improvement)
= 30 total measured configurations, out of 768 possible
```

Thirty labelled examples is *small-n regression*, not an absence of learning —
and it is precisely **why a Gaussian Process is the correct model class rather
than a neural network.** GPs are the standard tool when each label costs minutes
of computation and calibrated uncertainty is required from very few points
(Rasmussen & Williams, 2006; Shahriari et al., 2016).

#### Worked example — three rows of the GP's dataset

Three actual rows from `runs/20260909T172504Z/config_eval.csv` — iterations 1, 6
and 11 of the 30:

| Obs. | `t` | `b` | `p` | `g` | `c` | Encoded `x` | `y` = `energy_j` | On Pareto front? |
| ---: | ---: | ---: | :--- | ---: | ---: | :--- | ---: | :--- |
| 1 (seed) | 1024 | 1 | Q4_K_M | 14 | 2 | (1.000, 0.000, 0.000, 0.438, 0.000) | 143.69 J | No |
| 6 (seed) | 128 | 2 | Q4_K_M | 14 | 2 | (0.000, 0.333, 0.000, 0.438, 0.000) | 66.15 J | No |
| 11 (BO) | 128 | 2 | Q4_K_M | 14 | **4** | (0.000, 0.333, 0.000, 0.438, **0.500**) | **63.21 J** | **Yes** |

Read the third row as the loop working. Observation 11 is the first BO-guided
step, and the GP has proposed the seed-6 configuration **with one coordinate
changed** — CPU threads raised from 2 to 4. That is the surrogate exploiting a
learned gradient rather than sampling blindly: it lowers energy to 63.21 J and
is the first configuration to reach the Pareto front. Note also that `y` is a
*mean over the 50-prompt proxy workload*, not a single prompt.

#### The prior that seeds the first ten draws

The 10 seed configurations are not drawn uniformly. They are drawn from a
**task-informed prior** `P(precision | task)` (Table T1, `bopis/tasks.py`), which
is what connects component **B** to component **A**. Tasks are graded into three
quality-sensitivity tiers, and the more sensitive a task, the more prior mass is
kept on the safer, less-compressed variant:

| Sensitivity tier | Task categories | Share of 8-bit mass reassigned to Q4_K_M |
| :--- | :--- | ---: |
| HIGH | `closed_qa`, `information_extraction` | 0.25 |
| MEDIUM | `general_qa` | 0.40 |
| LOW | `open_qa`, `summarization`, `classification`, `creative_writing`, `brainstorming` | 0.50 |

### 1B — Data for the Naive Bayes classifier

Here the data is conventional, external, human-labelled and abundant — the
textbook case.

**Source:** the **Databricks Dolly 15k** instruction-following corpus (Conover
et al., 2023), an open dataset of instruction–response pairs written and
categorised by approximately 5,000 Databricks employees. Licensed CC BY-SA 3.0.

**Verified contents — 15,011 rows**, each with four fields: `instruction`,
`context`, `response`, `category`.

| Category | Rows | Carries `context`? | Quality-sensitivity tier |
| :--- | ---: | :---: | :--- |
| `open_qa` | 3,742 | No | LOW |
| `general_qa` | 2,191 | No | MEDIUM |
| `classification` | 2,136 | No | LOW |
| `closed_qa` | 1,773 | **Yes** | **HIGH** |
| `brainstorming` | 1,766 | No | LOW |
| `information_extraction` | 1,506 | **Yes** | **HIGH** |
| `summarization` | 1,188 | **Yes** | LOW |
| `creative_writing` | 709 | No | LOW |

**The class distribution is markedly unbalanced — 3,742 against 709, a ratio of
5.3 : 1.** This is not cosmetic; it dictates both the splitting protocol and the
choice of evaluation metric (§5B).

**Input (features), `x`.** Each instruction is converted to a bag of discrete
tokens. Four feature families, all fed to the same multinomial model:

| Feature family | Form | Rationale |
| :--- | :--- | :--- |
| Word unigrams | `w:<token>` | Lowercased words from the instruction |
| Leading word | `first:<token>` | Dolly annotators worked from per-category prompts, so the opening imperative ("summarize", "classify", "brainstorm") is unusually diagnostic and earns weight independent of its unigram count |
| Early bigrams | `bg:<a>_<b>` | Bigrams over the **first three tokens only** — separates "what are **some**" (brainstorming) from "what are **the**" (extraction) without inflating vocabulary |
| Context flag | `ctx:yes` / `ctx:no` | Whether a context passage was supplied — the single most discriminating feature, since exactly three categories carry context |

**A deliberate and defensible design decision:** the instruction and the context
are tokenized separately, and **the context contributes no word features — only
the `ctx:` flag.** Context passages average ~300 tokens against ~14 for
instructions; including their words would swamp the instruction's signal with
topical vocabulary irrelevant to *task type*. We are classifying what kind of
request this is, not what it is about.

**Vocabulary: 8,081 features** after a minimum-document-frequency cut of
`min_df = 2` (a feature must appear in at least two training documents), which
removes hapax legomena that cannot generalise.

**Target (label), `y`:** Dolly's own human-assigned `category` field — one of
eight classes.

**Split protocol — the part a panel will probe:**

```
Stratified 70 / 15 / 15,  random seed 20260101
  train       10,507 rows   -> fit the model
  validation   2,251 rows   -> select alpha, and NOTHING else
  test         2,253 rows   -> touched exactly ONCE, at the end
```

Three properties to state explicitly:

1. **Stratified**, because the corpus is unbalanced; an unstratified draw would
   give `creative_writing` an unstable test count.
2. **Seeded and fixed**, so the test set is stable across runs. A moving test set
   would let hyperparameter choices leak into the reported figure.
3. **The test set is never used for any decision.** α was chosen on validation
   alone. This is the discipline that makes 69.7% a *generalization* estimate
   rather than a training artefact (Hastie, Tibshirani & Friedman, 2009, ch. 7).

## ELEMENT 2 — TASK

> *"Task T"* (Mitchell, 1997). The formal problem being solved — stated as a
> mapping, not as a business goal.

### 2A — Task of the Gaussian Process surrogate

There are two nested tasks here, and conflating them is the most common error in
describing BOPIS.

**The outer task — constrained black-box optimization.** Find

```
x*  =  argmin  E(x)
        x ∈ X_feasible

subject to   SRR(x) ≥ 95 %        (speed retention)
             QRR(x) ≥ 98 %        (quality retention)
```

where `E(x)` is the energy consumed by the workload under configuration `x`.
This objective is **black-box** (no analytic form), **expensive** (each
evaluation costs minutes of real inference), **noisy**, and defined over a
**mixed discrete space**. That combination is the textbook motivation for
Bayesian Optimization (Jones, Schonlau & Welch, 1998; Shahriari et al., 2016).

**The inner task — supervised regression.** The GP itself performs

```
f : ℝ⁵ → ℝ × ℝ⁺
f(x) = ( μ(x), σ(x) )
```

Given an encoded configuration, return a predicted energy `μ(x)` **and a
calibrated standard deviation `σ(x)`.**

**`σ(x)` is the entire reason this is a Gaussian Process and not a linear
regression.** A plain regressor returns a number. A GP returns a number *plus an
honest, quantified admission of its own ignorance* — and Bayesian Optimization
spends its evaluation budget precisely on that ignorance.

**Task type classification:** supervised regression (continuous target),
conducted under an **active learning** protocol — the learner selects its own
next training point rather than receiving a fixed dataset (Settles, 2009).

**What is explicitly NOT part of this task:**

- Not per-prompt adaptation. Of the five parameters, only `t` is a per-request
  quantity; `b`, `p`, `g`, `c` are `llama-server` **launch flags**. A single
  running server cannot switch precision or GPU-layer count per prompt. **BOPIS
  selects one `x*` for the whole workload.**
- Not multi-objective regression. The GP has one target.
- Not language modelling.

### 2B — Task of the Naive Bayes classifier

**Supervised multiclass (8-way, single-label) text classification:**

```
h : instruction text × context-presence  →  { open_qa, closed_qa, summarization,
                                              classification, creative_writing,
                                              brainstorming, information_extraction,
                                              general_qa }
```

**Why this task exists at all — the gap it fills.** Stage 1 of the pipeline
requires `P(precision | task)` to weight the ten seed draws. During *evaluation*
the task label is free: it is Dolly's own ground-truth `category` field. During
*deployment* a user simply types a prompt and **there is no label.** That gap
previously had no implementation. The classifier closes it.

**The task's real-world role, stated precisely.** The predicted category is used
for exactly two things:

1. Selecting the prior `P(precision | task)` that weights **the 10 seed draws
   only** — not the 20 BO-guided steps.
2. Supplying the per-category quality floor `Q_min(task)` required by
   amendment A-26.

**This scoping is what makes a 69.7% classifier acceptable, and the argument
must be given proactively:** the 20 BO-guided evaluations follow Expected
Improvement over the GP, and `x*` is finally chosen by Pareto dominance plus the
SRR/QRR floors. **A misclassification makes the search slightly less
sample-efficient; it cannot make `x*` wrong.** The classifier biases where the
search starts looking, never what it is allowed to conclude.

#### Worked example — the task in action at deployment

```
User types:  "Give me five ideas for a team offsite."

  -> tokenize      first:give, w:give, w:me, w:five, w:ideas, ..., ctx:no
  -> classify      brainstorming      (posterior 0.83)
  -> prior lookup  P(p | brainstorming) = F32 0.10, F16 0.35,
                                          Q8_0 0.275, Q4_K_M 0.275
  -> effect        seed draws are weighted toward compressed variants,
                   because brainstorming is LOW quality-sensitivity
  -> UI            the prompt is badged "brainstorming", and the badge
                   states which classifier produced it
```

## ELEMENT 3 — MODEL

> The **representation** (Domingos, 2012): the hypothesis space, and the
> parameters that pick one hypothesis out of it.

### 3A — Model: Gaussian Process with an RBF kernel

A Gaussian Process is **a probability distribution over functions.** Rather than
committing to one curve through the data, it maintains a posterior over *every*
curve consistent with the observations — which is exactly what yields `σ(x)`.

Formally, `f(x) ~ GP(m(x), k(x, x'))`. Since `y` is standardized to zero mean
and unit variance before fitting (`y_mean = 124.59`, `y_std = 44.03` in our
reference run), a **zero-mean prior** `m(x) = 0` is appropriate.

**Kernel — RBF / squared-exponential:**

```
k(x, x') = σ_f² · exp( − ‖x − x'‖² / (2ℓ²) )
```

**The kernel encodes exactly one substantive assumption: similar configurations
consume similar energy.** That is a physically reasonable claim — 512 tokens and
513 tokens cannot plausibly differ in energy by an order of magnitude. The length
scale `ℓ` quantifies *how* similar, and is **learned from data, not set by us.**

**Posterior, given observations `X`, `y`** (Rasmussen & Williams, 2006, eq. 2.23–2.24):

```
μ(x*) = k*ᵀ (K + σ_n² I)⁻¹ y
σ²(x*) = k(x*, x*) − k*ᵀ (K + σ_n² I)⁻¹ k*
```

**Parameters — exactly three hyperparameters, `θ = {σ_f², ℓ, σ_n²}`:**

| Hyperparameter | Meaning | **Fitted value** (run `20260909T172504Z`) |
| :--- | :--- | ---: |
| `σ_f²` signal variance | How far the function ranges from its mean | **3.993** |
| `ℓ` length scale | Distance in encoded space over which energy stays correlated | **0.937** |
| `σ_n²` noise variance | Measurement noise in the energy observations | **0.00157** |

These are **learned**, not chosen — see §4A. That is the evidence that the GP is
genuinely *trained*: `GaussianProcess.fit()` at `bopis/gp.py:334` has the same
contract as scikit-learn's.

**Implementation notes worth defending:**

- Written **from scratch in the Python standard library** — no NumPy, no
  scikit-learn — and then **verified equivalent to the reference
  implementation.** `tests/test_gp.py::TestAgainstSklearn` checks the posterior
  mean, the posterior variance and the log marginal likelihood against
  `sklearn.gaussian_process`, and it passes (sklearn 1.7.0, numpy 2.0.2).
- Cholesky factorization with **escalating jitter**, because the kernel matrix
  becomes ill-conditioned when two evaluated configurations are close in encoded
  space — which Bayesian Optimization actively *causes* as it converges.

### 3B — Model: Multinomial Naive Bayes

A generative probabilistic classifier. It models `P(class) · P(features | class)`
and returns the class maximising the posterior (Manning, Raghavan & Schütze,
2008, ch. 13; McCallum & Nigam, 1998):

```
ŷ = argmax_c [  log P(c)  +  Σ_{i ∈ tokens} count_i · log P(token_i | c)  ]
```

**The "naive" assumption:** features are conditionally independent given the
class. This is **false** for natural language — "machine" and "learning"
plainly co-occur. It is nonetheless a strong and well-documented performer on
topical text classification, because the decision only requires the *argmax* of
the posterior to be right, not the posterior itself to be calibrated.

**Smoothing** — add-α (Lidstone):

```
P(token | c) = (count(token, c) + α) / (Σ_t count(t, c) + α · |V|)
```

Without α, a single unseen token in a test instruction would drive the entire
posterior for that class to zero.

**Parameters of the fitted model:**

| Quantity | Value |
| :--- | ---: |
| Classes | 8 |
| Vocabulary `\|V\|` | **8,081** features (`min_df = 2`) |
| Learned log-priors `log P(c)` | 8 values |
| Learned log-likelihoods `log P(token \| c)` | 8 × 8,081 ≈ **64,648** parameters |
| Hyperparameters | **one** — α |
| Selected α | **0.5** (chosen on validation) |

**Why this model class was selected** — three reasons, all defensible:

1. It has a **closed-form maximum-likelihood fit**, so there is no optimizer to
   tune, no learning rate, no random seed and no convergence risk. The fit is
   deterministic and reproducible by construction.
2. It requires **no third-party package**, preserving the project's
   standard-library-only policy (breached only by the offline BERTScore stage).
3. It is the **conventional strong baseline** for small-vocabulary topical text
   classification, and Dolly's categories are largely distinguished by imperative
   verbs — exactly the signal a bag-of-words model captures.

**Cross-implementation verification:** the model is exported to `bopis_model.js`
so the browser UI can badge prompts live. The browser's Naive Bayes scoring was
checked against the Python implementation on **155 real Dolly rows: 155/155
agree, maximum confidence delta 0.0** — bitwise-identical posteriors, not an
approximation.

## ELEMENT 4 — LEARNING ALGORITHM

> The **optimization** component (Domingos, 2012): the procedure that searches
> the hypothesis space and returns fitted parameters.

### 4A — Learning algorithm for the GP: marginal likelihood + Expected Improvement

Two distinct algorithms operate in a loop. Keep them separate.

#### (i) Fitting the GP — maximize the log marginal likelihood

Hyperparameters `θ = {σ_f², ℓ, σ_n²}` are learned by maximizing

```
log p(y | X, θ) = −½ yᵀ(K + σ_n²I)⁻¹y  −  ½ log|K + σ_n²I|  −  (n/2) log 2π
                  └─ data fit ─┘         └─ complexity penalty ─┘
```

This objective **automatically embodies Occam's razor** (Rasmussen & Williams,
2006, §5.4): the first term rewards fitting the data, the second penalises
over-flexible kernels. No held-out set is required to prevent overfitting of the
hyperparameters — the penalty is built in.

**Optimizer — and an honest deviation from the manuscript (amendment A-7):**
Chapter 3 states L-BFGS-B. L-BFGS-B is a gradient-based quasi-Newton method with
**no standard-library implementation**, and supplying analytic kernel gradients
would add substantial code for little benefit at this problem size. The
implementation instead uses a **coarse log-space grid search followed by
multi-start Nelder–Mead** (a derivative-free simplex method). At three
hyperparameters and ≤ 30 observations the two find indistinguishable optima, and
the grid stage additionally guards against the local minima that make
single-start quasi-Newton GP fits unreliable. **Achieved log marginal likelihood:
−12.41.**

#### (ii) Choosing the next point — Expected Improvement

```
imp   = f(x⁺) − μ(x)          ← minimizing energy, so improvement is a DECREASE
Z     = imp / σ(x)
EI(x) = imp · Φ(Z)  +  σ(x) · φ(Z)
         └ exploitation ┘      └ exploration ┘
```

where `f(x⁺)` is the best energy measured so far (Jones, Schonlau & Welch, 1998).

> **Note for the panel — an error we found and fixed ourselves.** The manuscript
> originally printed the *maximisation* form, `imp = μ(x) − f(x⁺)`. Because BOPIS
> **minimizes** energy, that expression rewards configurations predicted to
> consume *more* energy, and a search driven by it would converge on the worst
> configuration in the space. The **code was always correct**
> (`bopis/acquisition.py:72-74`, `improvement = f_best - mu - xi`, with
> `tests/test_acquisition.py` asserting EI prefers lower μ); the manuscript text
> has now been corrected under amendment A-2.

#### (iii) The full loop

```
1.  Draw 10 seed configurations, weighted by P(precision | task)   [component B]
2.  Measure each -> 10 observations (x, E)
3.  Repeat 20 times:
      a. FIT the GP on all observations so far (refit from scratch, every time)
      b. Score EI(x) over all unevaluated feasible configurations
      c. Run the argmax-EI configuration on real hardware
      d. Append the measurement
4.  Non-dominated sort the 30 results over (E↓, S↑, Q↑)  -> Pareto front
5.  Filter survivors by SRR ≥ 95% AND QRR ≥ 98%
6.  x* = argmax EIR(x) among survivors
```

**Contrast with conventional supervised learning — the table to memorise:**

| Conventional ML | Bayesian Optimization (ours) |
| :--- | :--- |
| Thousands of labelled examples, given in advance | **30** evaluations, **created by the learner** |
| Fit once, then predict | **Refit from scratch after every single evaluation (20×)** |
| Goal: generalize to unseen data | Goal: **locate the optimum in this space** |
| "Training set" | "Observations" |
| Epochs, gradient descent, learning rate | **None of these exist here** |

So the honest answer to *"do you train BOPIS to pick lowest energy with best
speed and quality?"* is: **BO hunts for low energy; Pareto analysis plus the
SRR/QRR floors guarantee speed and quality were not sacrificed to obtain it.
Two stages, not one trained model.**

#### Worked example — Expected Improvement, by hand

After three evaluations: c1 = 28.0 J, **c4 = 22.0 J (best, so `f(x⁺) = 22.0`)**,
c7 = 41.0 J. The GP now reports μ and σ for three unevaluated candidates:

| Candidate | μ(x) | σ(x) | imp = 22 − μ | Z | Φ(Z) | φ(Z) | **EI** |
| :--- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| **A** | 20.0 | 1.00 | +2.0 | 2.00 | 0.9772 | 0.0540 | **2.008** ✅ |
| **B** | 26.0 | 8.00 | −4.0 | −0.50 | 0.3085 | 0.3521 | **1.583** |
| **C** | 21.5 | 0.05 | +0.5 | 10.00 | ≈1.000 | ≈0.000 | **0.500** |

*Arithmetic for B:* `(−4.0 × 0.3085) + (8.0 × 0.3521) = −1.234 + 2.817 = 1.583`

**Read the ranking carefully — it is the entire intuition of Bayesian Optimization:**

- **A wins**: predicted better than the incumbent *and* reasonably certain.
- **B places second even though it is predicted WORSE than what we already have**
  (26 J vs 22 J). Its σ = 8.0 means the GP has almost no idea what is there — it
  could plausibly be 18 J. That possibility is worth buying. **This is exploration.**
- **C places last even though it is predicted BETTER than the incumbent** (21.5 J).
  Its σ = 0.05 means we already effectively know the answer, so there is nothing
  left to learn. **A greedy optimizer would pick C and stall.**

### 4B — Learning algorithm for Naive Bayes: closed-form MLE + validation search

**There is no iterative optimizer.** The maximum-likelihood fit is obtained by
**counting**, in a single pass over the 10,507 training documents:

```
Step 1.  Build the vocabulary; discard features with document frequency < 2
         -> |V| = 8,081

Step 2.  log P(c) = log( N_c / N )                      for each of 8 classes

Step 3.  log P(token | c) = log( (count(token,c) + α) /
                                 (Σ_t count(t,c) + α·|V|) )

Step 4.  Precompute the unseen-token mass log( α / total_c ) once per class,
         rather than recomputing it at every lookup
```

This is a genuine **maximum-likelihood estimate under the multinomial
likelihood** — it simply happens to have a closed form, so no gradient descent,
no learning rate and no seed are needed. **Determinism is a feature:** re-running
the fit reproduces the model exactly.

**Hyperparameter selection — the only search that occurs.** α is chosen by grid
search over `{0.01, 0.05, 0.1, 0.25, 0.5, 1.0, 2.0}`, scored on the **validation
split only**:

| α | Validation exact accuracy |
| ---: | ---: |
| 0.01 | 69.0% |
| 0.05 | 70.4% |
| 0.10 | 70.7% |
| 0.25 | 70.7% |
| **0.50** | **70.9%  ← selected** |
| 1.00 | 70.4% |
| 2.00 | 68.8% |

The curve is appropriately shaped: too little smoothing (0.01) over-trusts rare
tokens; too much (2.0) washes out the discriminative signal. **The test set played
no part in this selection** — that is what licenses the §5B figure as an estimate
of generalization.

## ELEMENT 5 — EVALUATION

> *"Performance measure P"* (Mitchell, 1997). How we decide whether the learning
> worked — with criteria fixed **before** the numbers were seen (Jain, 1991).

### 5A — Evaluating the GP surrogate

Four metrics, on two bases. Reporting both bases is a deliberate honesty
measure.

| Metric | Definition |
| :--- | :--- |
| **MAE** | Mean absolute error between μ(x) and measured energy, in joules |
| **NPE** | Normalized prediction error — MAE as a % of mean measured energy. Acceptance threshold **< 10%**, researcher-defined per Jain (1991) |
| **R²** | Coefficient of determination |
| **UCR** | **Uncertainty Coverage Ratio** — the fraction of observations falling inside the GP's own 95% credible interval. Target **≥ 0.95**. This checks that σ(x) is *calibrated*, not merely present |

**UCR deserves emphasis in a defense.** MAE and R² only assess the mean. UCR is
the metric that validates the *uncertainty* — and uncertainty is the whole reason
a GP was chosen. A model with excellent R² and UCR = 0.60 would be systematically
overconfident and would break Expected Improvement.

**Results — run `20260909T172504Z`:**

| Basis | n | MAE | NPE | R² | UCR | Verdict |
| :--- | ---: | ---: | ---: | ---: | ---: | :--- |
| **Leave-one-out CV** ← *primary* | 30 | **4.70 J** | **3.77%** | **0.980** | **0.967** | ✅ passes both thresholds |
| One-step-ahead ← *pessimistic bound* | 20 | 8.76 J | 8.03% | 0.799 | 0.85 | ✅ still under the 10% NPE threshold |

**Why two bases, and why LOOCV is the primary figure (amendment A-40).**
One-step-ahead predictions are recorded *before* each configuration is run, from
a GP fitted only on previous iterations — genuinely out-of-sample. But **Expected
Improvement by design probes exactly where the GP is least certain.** Scoring the
surrogate on its own deliberate probes measures the *exploration policy*, not the
model's accuracy — which is why R² drops to 0.799 there. LOOCV (Arlot & Celisse,
2010) scores the surrogate on all 30 points evenhandedly and is the correct
reliability figure. We report both, and label the pessimistic one as such.
**MobileLLM-Flash (2026) is the direct precedent**, reporting a cross-validated
GP surrogate R² = 0.97 on ~800 on-device measurements; our LOO R² = 0.980 sits in
the same regime.

**Evaluating the optimization outcome — the three thesis-level dependent
variables.** These evaluate the *system*, not the surrogate:

| Metric | Formula | Success criterion |
| :--- | :--- | :--- |
| **EIR** — Energy Improvement Ratio | `[(E_default − E_BOPIS) / E_default] × 100%` | **> 0** |
| **SRR** — Speed Retention Ratio | `(S_BOPIS / S_default) × 100%` | **≥ 95%** |
| **QRR** — Quality Retention Ratio | `(Q_BOPIS / Q_default) × 100%` | **≥ 98%** |

A configuration is *BOPIS-optimal* only if all three hold simultaneously
(`bopis/metrics.py:83`). Quality `Q` is BERTScore F1 (Zhang et al., 2020) against
Dolly's reference responses.

**Protocol.** All three conditions — unoptimized default, random-search winner,
BOPIS winner — are evaluated on the **identical fixed stratified 500-prompt Dolly
sample**, with a nested 50-prompt proxy subset used during the search. Seats are
allocated across the eight categories proportionally by the **largest-remainder
(Hare–Niemeyer) method**, because proportional allocation of 500 gives fractional
targets: on the unfiltered category counts this yields
125 / 73 / 71 / 59 / 59 / 50 / 39 / 24 = 500 exactly. (Quality filtering runs
*before* allocation, so the shipped figures are recomputed against the surviving
pool.) Sampling uses a seeded `random.Random` without replacement and the
selected row IDs are written to CSV, so the exact sample is reconstructable.

Using the same prompts for all three conditions is what makes the comparison
attributable to the *configuration strategy* rather than to different user
questions.

**Statistical treatment** (`bopis/stats.py`):

- **Friedman test** (Friedman, 1937) — non-parametric, for ordering across the
  three related conditions over the 500 paired prompts.
- **Nemenyi post-hoc** at α = 0.05 — for pairwise differences following a
  significant Friedman (Demšar, 2006).
- **Paired bootstrap 95% CI** (Efron & Tibshirani, 1993), 10,000 resamples,
  resampling *prompts* rather than conditions, since all three conditions see the
  same prompt set. Reported as e.g. *"estimated EIR = 22.4% (95% CI 18.1–26.9%)."*
  Friedman/Nemenyi test **ordering**; the bootstrap gives **effect size**. Both
  are needed.

**The methodological result worth presenting — systematic bias cancels.** The
study GPU (NVIDIA MX330) exposes no power sensor; both `nvmlDeviceGetPowerUsage`
and `nvmlDeviceGetTotalEnergyConsumption` return `NVML_ERROR_NOT_SUPPORTED`.
Energy is therefore *estimated* by a two-component linear load-line model
(the form originates in datacenter power provisioning — Fan, Weber & Barroso,
2007; evaluated by Rivoire, Ranganathan & Kozyrakis, 2008 — and is the same
approach as Green Algorithms, Lannelongue et al., 2021). If the estimator's bias
is multiplicative, `Ê = k·E`, then:

```
EIR̂ = (k·E_def − k·E_bop) / (k·E_def) = (E_def − E_bop) / E_def = EIR
```

**`k` cancels identically.** The ±30% nameplate uncertainty is exactly such a
multiplicative scale error, so it does not propagate into EIR at all. The **ratio**
is defensible today; **absolute J/token is not**, and we say so.

### 5B — Evaluating the Naive Bayes classifier

**Protocol:** a single pass over the 2,253-row held-out test set, compared
against the 42-rule baseline classifier (`bopis/classify.py`) on the **same
split**. Three accuracy bases are reported, because exact 8-way accuracy is not
the quantity the system actually depends on.

| Basis | Rule baseline | **Learned model** | Delta |
| :--- | ---: | ---: | ---: |
| Exact 8-way | 48.2% | **69.7%** | **+21.4 pts** |
| `open_qa`/`general_qa` merged | 63.6% | **78.6%** | +15.0 pts |
| **Quality-sensitivity tier** ← *the operationally relevant figure* | 67.1% | **79.2%** | +12.1 pts |

**Quote the tier figure in a defense.** The prior `P(precision | task)` is keyed
to the three-tier sensitivity grade, not to the eight-way label. Confusing
`open_qa` with `general_qa` moves the prediction across a tier boundary in only
some cases; confusing it with `closed_qa` matters far more. The tier basis
measures what the downstream system is actually sensitive to.

**Per-category breakdown — and the finding that argues for a hybrid:**

| Category | Rules | **Learned** | Test n |
| :--- | ---: | ---: | ---: |
| `open_qa` | **78.5%** | 77.0% | 562 |
| `closed_qa` | **89.1%** | 81.2% | 266 |
| `summarization` | 20.2% | **58.4%** | 178 |
| `classification` | 33.3% | **91.9%** | 321 |
| `creative_writing` | 34.6% | **54.2%** | 107 |
| `brainstorming` | 41.5% | **64.5%** | 265 |
| `information_extraction` | 36.3% | **58.4%** | 226 |
| `general_qa` | 11.3% | **49.1%** | 328 |

**Three things to report honestly — volunteer all three:**

1. **Generalization gap.** Train accuracy is **81.5%** against 69.7% on test — an
   ~11.8-point gap. That is moderate and expected for a bag-of-words model over
   8,081 features fitted on 10,507 documents. State it; do not hide it.

2. **The residual error is largely intrinsic, not a model failure.** The dominant
   confusion is `general_qa` ↔ `open_qa`: **132 + 68 = 200 of the errors**, the
   single largest error class. Dolly separates those two categories by whether
   answering requires a specific retrievable fact or general world knowledge — a
   property of the **answer**, not of the instruction's surface form. **No
   classifier operating on the instruction alone can recover that distinction.**
   This is a ceiling imposed by the label definition, and it is why the
   QA-merged basis is also reported.

   Remaining confusions: `brainstorming → general_qa` (54),
   `information_extraction → closed_qa` (53), `summarization → closed_qa` (50) —
   the last two both being context-bearing categories, as expected.

3. **The rule baseline is optimistic, so +21.4 pts is a lower bound.** The rule
   weights in `bopis/classify.py` were hand-tuned while observing whole-corpus
   accuracy, so the baseline has **effectively already seen the test set.** Its
   48.2% is therefore flattering, and the learned model's true margin is larger.
   Stating this unprompted is the single strongest credibility move available in
   this section.

**A genuine finding, not a weakness:** the rules still **beat** the learned model
on `closed_qa` (89.1% vs 81.2%) and `open_qa` (78.5% vs 77.0%), where the
structural context gate is a very strong signal that a bag-of-words model
dilutes. **A gate-then-model hybrid would likely beat either alone** — a concrete,
motivated item for Future Work.

## 7. Anticipated questions, with short answers

**"Where is your loss function?"**
Deliberately outside this document's scope. For completeness: the GP is fitted by
maximizing the log marginal likelihood (equivalently, minimizing its negative),
and Naive Bayes maximizes the multinomial likelihood in closed form. Neither is a
hand-designed loss in the deep-learning sense.

**"Thirty training examples is not machine learning."**
It is *small-n regression*, and it is exactly the regime Gaussian Processes exist
for. Each label costs minutes of real inference, and the application requires
calibrated uncertainty from few points. A neural network would be the wrong model
class here, not a more rigorous one. Our LOO R² = 0.980 is a measured result, and
the implementation is verified equivalent to scikit-learn.

**"Is this supervised, unsupervised, or reinforcement learning?"**
Supervised, in both components. The GP additionally operates under **active
learning**, because it chooses its own next training point. Nothing is
unsupervised — Pareto non-dominated sorting is a deterministic selection
algorithm, not a learner. Not reinforcement learning: no state, no transitions,
no policy, no temporal credit assignment.

**"You only get 69.7% accuracy."**
On the basis that drives the system — the quality-sensitivity tier — it is 79.2%,
against a hand-tuned baseline's 67.1%. And the classifier weights only the 10
seed draws out of a 30-evaluation budget. A misclassification costs
sample-efficiency; it cannot make `x*` wrong.

**"Does the system adapt per prompt?"**
No, and the manuscript has been corrected on this point. Only `t` is a
per-request parameter; `b`, `p`, `g`, `c` are `llama-server` launch flags. BOPIS
selects **one `x*` for the workload.** Per-prompt adaptation over the full tuple
would require a pool of warm servers — identified as Future Work.

**"Are these energy results measured?"**
No, and we state it first rather than waiting to be asked. The MX330 exposes no
power sensor, so energy is a labelled Mode C estimate, and every recorded run
currently uses the simulator backend. The **ratio** EIR survives this intact
because multiplicative bias cancels (§5A). Absolute J/token does not, and we do
not claim it. The classifier results in §5B are, by contrast, fully real.
